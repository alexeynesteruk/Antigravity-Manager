## Native credential storage

The reviewed candidates did not establish a ready cross-platform native vault implementation to import. The relevant source evidence is [larry109 PR 1](https://github.com/larry109/Antigravity-Manager/pull/1): its `modules/integration.rs` replaces macOS Keychain `-A` with `-T` for detected Antigravity applications. Its own `SECURITY-FORK.md` correctly discloses that the creating `/usr/bin/security` binary still has access and that `-w <token>` exposes the credential in process arguments. The patch is partial hardening, not a native API conversion.

Use native macOS Keychain calls for manager vault secrets and Windows Credential Manager; Linux Secret Service tooling must receive secrets through stdin, with bounded execution and fail-closed errors. Headless environments without an available service need an explicit supported policy rather than a silently weaker fallback. Updating existing IDE/ACP credential integration ACLs is a separate compatibility-sensitive concern.

## Candidates to exclude or separate

- [cc1027114472 PR 1](https://github.com/cc1027114472/Antigravity-Manager/pull/1), merged at [`047791cb`](https://github.com/cc1027114472/Antigravity-Manager/commit/047791cb0cf2576471147067da238d783870c854), adds a four-attempt recovery scheduler. Its `auto_recovery.rs` probes a fixed `gemini-2.5-flash`; `token_manager.rs` immediately probes after 429 and clears limits on probe success. This can erase a model-specific lock based on another model's response and introduces extra upstream traffic. Keep the integrated versioned probe ownership, cooldown budgets, restriction stops and current model eligibility instead of adopting this scheduler wholesale.
- [SanHsien PR 30](https://github.com/SanHsien/Antigravity-Manager/pull/30) is a documentation triage of validation follow-ups, explicitly stating no runtime fix was imported. It is not evidence of implemented account restriction recovery.
- [AlvinPlayz23 PR 1](https://github.com/AlvinPlayz23/Antigravity-Manager/pull/1) is still open and changes an older auth implementation to hand-written constant-time comparison. Do not replace current admission code with that old file. A separately scoped credential comparison audit may be useful; the PR does not address account eligibility, restriction stops or egress.
- [ezBuilder PR 5](https://github.com/ezBuilder/Antigravity-Manager/pull/5) combines startup masking with unrelated third-party routing. Startup secret removal can be implemented directly; do not import its routing/fallback behavior to obtain that small improvement.

TLS/client fingerprints, identity rewriting and device-ID rotation are not established account-protection mechanisms. This review recommends credential confidentiality, authenticated exposure, conservative restriction handling, bounded retries and explicit egress behavior; it makes no claim that these prevent provider account restrictions.
