# Deep gateway review — November 12, 2026

Baseline: `abbb4da87c751f2797a5940317f6cb889837e0b4`. The requested scope covers the gateway and Google-facing behavior, prioritizing reproducible defects. Three agents reviewed persistence/frontend, OAuth/security/media, and CI/release; the primary agent reviewed streaming and cross-checked the patches. Fixes are local on the already-authorized `main` branch. No real Google credentials, authenticated Google probes, release publication, or cloud builds were used in this review.

| P2 | Responses finalization could wait indefinitely for a session-store acknowledgement after output generation had finished. | The shared lifecycle bounds the barrier using the existing configurable stream idle duration. Missing acknowledgement withholds completion frames and still runs finish cleanup. The first-data fix deliberately prefers byte preservation when a heartbeat is fragmented or ambiguous. Such a fragment may count as first data for timing instead of being skipped; it is not discarded. Finalization uses the existing `stream_timeouts.streaming_sliding_secs` setting, so GUI/config/headless users retain the same knob rather than acquiring a separate hidden timeout.

After an index-first deletion partially fails, credentials can remain on disk while absent from the active index. The scheduler's existing orphan filter excludes those files. Cleanup requires reviewing current account state: an import already in flight can reuse an old ID, so blindly repeating a stale deletion can affect a newly restored account. This patch does not introduce a generation-aware cleanup API or a deletion journal.

## Remaining findings and improvements

These were source-reviewed; they are not claimed fixed or all exercised at runtime.

1. **Configured proxy failures can fall back to default/direct routing.** `proxy/upstream/client.rs::get_client` and default-client rebuild, plus shared proxy-client helpers, prioritize availability after construction/lookup errors. A configured per-account route therefore is not a fail-closed egress-isolation guarantee. Strict routing needs an explicit policy and error propagation across inference, OAuth and discovery; it should not be implemented as fingerprint spoofing.
2. **Several accounts share HTTP clients.** The default client is shared and per-proxy clients are cached by proxy entry, not account. Connection pools can consequently be reused across account requests. Whether Google uses this for classification is unknown; the code does not establish account unlinkability.
3. **Stream activity remains too broad, and partial-frame memory is unbounded.** `stream_lifecycle.rs` renews activity on any nonempty incoming transport chunk, even when no new model content is produced. The partial-line buffer has no explicit size cap. A future fix should distinguish model progress from transport keepalive and expose suitable frame limits without truncating legitimate large image/tool events.
4. **Rotated refresh tokens can be discarded by callers.** `oauth.rs::ensure_fresh_token` and the quota-refresh caller retain the previous refresh token when constructing updated account data. A provider rotation could make the next exchange fail. Google rotation frequency and the current user's actual token responses were not measured.
5. **Batch-import reconciliation drops state.** Positive ban evidence in a prepared existing account is not fully copied into the latest stored account, although forbidden quota still blocks immediate selection. A valid replacement token imported in a batch also does not clear the credential-invalid disabled state as single upsert does. Preserve independent manual locks, and clear only successfully recovered credential failures.
6. **Other persistence races remain.** Whole-entity read-time healing can save a previously read account over a newer token/flag write. Pending cache deletion is keyed by an unversioned account ID, so a concurrent import reusing the ID can later be removed from memory by an older deletion signal. Index-only reconciliation does not solve those classes.
7. **Some accepted media representations are inconsistent.** URL-safe padded Base64 accepted by the older Chat sanitizer is now rejected by standard-only ingress; native Gemini/Claude inline fields behave differently. Claude HTTPS image/document sources pass source admission but the current typed mapper omits the URL and can silently drop the part. Return explicit unsupported-input errors or implement supported normalization.
8. **Proxy URL credentials enter INFO logs.** Some configured proxy URLs are logged without removing userinfo in inference and shared client builders. This is a local console/GUI log exposure, not evidence those logs are uploaded to Google. Redact userinfo consistently.
9. **Preview publication is not resumable after its final metadata upload fails.** A beta release can already be public when preview upload fails; normal rerun then refuses to overwrite the public release. Separate immutable publication from an idempotent, verified channel-finalization operation.
10. **Version bump is not fully atomic.** Mandatory missing/unmatched manifests can warn after other files have changed. The subsequent unlocked `cargo check` can alter resolution and swallow failures; some prerelease strings pass bump validation but fail the release gate. Validate every target first and stage all replacements before committing changes.
11. **Independent fork updates require a deliberate channel/key decision.** The app still trusts upstream's updater public key and upstream release URLs, while fork release metadata points to this fork. Do not silently replace trust roots or assume an independently configured signing secret matches the embedded key.

The scheme-less proxy URL hypothesis was ruled out: the installed rquest parser supplies the HTTP scheme itself. Existing trusted-forwarding protection and local-media filesystem restrictions remain intact.
